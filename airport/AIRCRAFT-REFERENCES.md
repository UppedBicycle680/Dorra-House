## Interpretation and limits

- King Air 350i's manufacturer URL now presents the 360, which retains the same relevant external airframe dimensions. The model represents the 350 with four-blade propellers.
- E175 span uses the extended-winglet operator configuration; early E175s with smaller winglets have a different span. The generic catalogue name does not imply every E175 variant has the same dimensions.
- The 767 manufacturer page gives the 767-300 freighter's shared external airframe dimensions; this game's regular 767-300 model has passenger windows.
- Published planning measurements can vary slightly with rounding, loading, tyre/strut state or measurement datum. They are used for visual proportions, not operational clearance calculations. Internal fuselage loft radii, sweep, window placement, engine diameters and wheel shapes are artist approximations. Gate, runway and equipment requirements remain the separate simplified game rules.
- All meshes use world geometry for heading, altitude, tail height, engine positions and animated propeller blades. The optional gearDown presentation flag controls retraction; fixed-gear Cessnas always retain their wheels. Gear defaults down so an approach does not hide its landing gear merely because of altitude. The scene renderer owns shadows and paths. Unknown draw IDs use the C172 fallback; fleet SVGs require a known ID.
- Mriya is a fictional heritage operation in this game; the visual reference represents the historical aircraft.

`sourceIds` in the module map to the row with the same ID, except `cessna-172` → c172, `cessna-caravan` → caravan, `dash-8` → q400, `atr-42` → atr42 and `atr-72` → atr72.

## Rendering verification

The independent model check covers all 22 catalogue IDs, exact mesh length/span extents, finite coordinates, engine and propeller counts, and ground/propeller clearance. Every type was drawn at −90°, 0°, 90° and 180° using the production Canvas function; closer production-renderer screenshots cover a 747 approach, landing, taxi, take-off and climb. The fleet's self-contained SVG images use the same geometry, with descriptive alternative text and visible length/span values.

The mature 12-gate Brisbane test uses the production UI, renderer, assets and styles with a browser-scoped read-only public-view fixture. After warm-up, a four-second sample from the renderer's own frame counters gave:

These are local headless Chromium measurements, not a guarantee for every machine. The map caps its backing bitmap at six million pixels; DOM text retains device resolution. Parked aircraft and static airport scenery are cached, moving aircraft remain world-projected, and the map pauses behind a modal. Fleet art is decoded during idle time and uses 22 SVG-backed images, reducing the open page from roughly 8,300 DOM elements to 426.

## Artwork refinement — 8 September 2026

The model pass described in [PLANE-MODEL-IMPROVEMENT-PLAN.md](PLANE-MODEL-IMPROVEMENT-PLAN.md) retains all variants, dimensions and source assignments above. It refines the original artwork with surface-attached windows, split cockpit panes, lateral fin thickness, cambered wings, blended raised tips, raked tips, recessed jet intakes/exhausts, turboprop spinners and a revised 747 upper-deck transition. The 737 uses a flattened lower nacelle contour rather than compressing its entire cross-section.

These refinements are artist approximations derived from the existing recognition features, not new manufacturer measurements. Door positions, wing sections, nose shapes, nacelle internals and wheel arrangements are simplified. Jet nose length now follows body width so stretched variants gain cabin length without proportionally stretching the nose. The A350 receives its own raised-tip bend height. The original published length/span/height checks remain in force.

The shared Canvas/SVG projection now culls back-facing surfaces and calculates depth from the camera projection. Small door, fan and highlight polygons are omitted below 180 projected fuselage pixels; the catalogue uses a consistent close-up scale. Cached geometry, face centres, lazy vertex projection and parked-aircraft caching keep the additional artwork affordable.

Current validation, before/after comparisons and paired performance measurements are recorded in [the September 8 results](../output/playwright/plane-model-improvements/RESULTS.md). Reproduce the independent dimension, skin-attachment, fin, gear and reduced-motion checks with `node airport-aircraft-regression.mjs`. Run `node output/playwright/airport-performance-check.mjs --paired` to compare the saved baseline module and delivered module consecutively for each viewport/DPI; the historical measurements above are not the new pass's benchmark.
