# War world and equipment data

Rebuild with `python -m pip install shapely==2.1.2`, then `python scripts/build-war-world.py` from the repository root. Python 3.11+ and Node 22+ are required. Raw inputs are cached only in ignored `work/war-source`. The script validates pinned SHA-256 hashes before processing and emits a versioned manifest, country map, one real province geometry chunk per country, national profiles, platform data, naval routes and bounded transactional SQL seed files.

After changing only equipment definitions or prices, `python scripts/build-war-world.py --catalog-only` refreshes catalogue JSON and all seed chunks without rebuilding geography. Facility quotes share the authoritative level-one price of 1,500 cash, 500 supplies, 200 electronics and 100 manpower; cash/supplies/electronics scale by the next level, while manpower remains fixed. Build time is six game hours per next level. Platform research prices use the exact server numeric formulas, including fractional values.

Geography uses the public-domain [Natural Earth v5.1.2 release](https://github.com/nvkelso/natural-earth-vector/tree/v5.1.2): 10m admin0 countries, 10m admin1 states/provinces, populated places, ports, and geography regions. “10m” means a map scale of 1:10 million. It does not mean a ten-metre ground resolution. These historical cartographic boundaries do not assert diplomatic recognition or current territorial control. ISO country identifiers are retained where unique; Natural Earth identifiers distinguish special and disputed areas. Province IDs come from the source `adm1_code`; a country footprint is used only when the source contains no admin1 division. No synthetic cell grid replaces the administrative boundaries.

All 258 source map regions remain available, with 204 populated selectable country/scenario profiles. Source Dependency, Lease and nonprimary Country regions use the primary parent's `SOV_A3` group for game ownership. Indeterminate and Disputed areas retain separate scenario IDs; the grouping does not assign Palestine to Israel. Each province preserves `regionId` for its geometry chunk and uses sovereign-parent `countryId` for match ownership. Parent nation `regionIds` lists every required chunk, including Denmark's Greenland and Faroe Islands. French Guiana is already part of the source France footprint (`FRA-2000`); the metadata alias `GF -> FR` records that source representation. These are dataset conventions for the scenario, not additional sovereignty claims.

Land neighbours require a positive-length shared original boundary before simplification. Country and province shapes use topology-aware simplification with four-decimal output coordinates. City and capital labels come from populated-place points. Where the source has no capital point, `capitalFallback:true` marks the scenario seat explicitly. Port status derives from actual Natural Earth port points; the source warns that port coordinates can represent a nearby city. Coarse terrain classes use named mountain, plateau, desert, tundra and wetland region overlaps; they are game terrain categories, not terrain surveys.

`naval-routes.json` is an illustrative game-routing graph. Its ocean waypoints are tested against source land polygons; land-crossing links are rejected. A province needs a mapped port and a valid water connection to join that graph. These routes are not safe-navigation instructions, hydrographic charts or real shipping-lane claims. Closely spaced islands and narrow canals can be omitted at this scale.

National economy values retain Natural Earth's historical GDP estimates and their source years. `economy` is GDP in USD billions; it is not a current forecast. `military` is an authored game strength index based on curated platform coverage and economy, not a real military ranking. No starting formation count claims to reproduce a real order of battle.

Equipment definitions live in `war/catalog.mjs`, with government, armed-forces and manufacturer source links on each named platform. The catalogue is a representative, conservative roster rather than a complete global inventory. Nation/operator allowlists restrict hardware; undelivered future programmes and fictional designs are excluded. Family-level rows explain that national variants differ. Universal infantry, engineering, logistics, observers and command programmes are explicitly marked `abstractCapability:true`; those are scenario capabilities and never claims that every nation owns the same equipment. Areas without an authored hardware roster receive only those labelled baseline capabilities. A customer selection or future order alone is not intended to establish operational service.

Diplomatic import licences are a game system. Export eligibility is conservative: nuclear programmes, baseline abstractions and single-operator domestic hardware are marked `exportable:false`, including F-22, B-2 and J-20. A game licence is not a claim of a real export authorization.

All prices, research/build durations, attack/defence values, ranges, visibility, radar, stealth and electronic-warfare effects are original game-balance abstractions. They are not classified data or manufacturer performance estimates. Nuclear forces remain high-level strategic abstractions with strict national availability; Israel's status is marked undeclared. No weapon construction or operational targeting instructions are included.

Apply the war-schema migration first, then `scripts/war-seed/*.sql` in lexical order. Seed files only upsert catalogue rows; they contain no player state and no credentials. Generated geometry stays outside the database to keep match queries bounded. Run `node --test tests/war-catalog.test.mjs` after regeneration.
